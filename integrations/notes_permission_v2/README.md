# Notes v2 permission pairing candidate

This package prepares the existing Control Notes permission button and a bounded, signed Notes helper from reviewed v0.4.0 source. It is source only: no helper/profile is installed, no Notes Automation prompt is sent, and no note content is accessed. The helper's data profile stays `enabled=0`; append and attachment work remain disabled.

`UPSTREAM-PINS.json` preserves the 16 upstream Notes v2 Swift/build input hashes. `PROPOSED-DELTAS.json` names the one changed upstream file, its original hash, and its candidate hash; that change requires independent review. `prepare_permission_candidate.py` also checks the three shared Apple review inputs. It verifies the installed Control with the existing ARL certificate and exact `local.arl.control` bundle ID, then records the current executable SHA and CDHash as action-time evidence. It does not require a particular Control release CDHash. `verify_closure.py` checks the same source and identity without building or requesting TCC.

At an approved, user attended first use, `prepare_permission_candidate.py` produces a signed `ARLNotesBridge.app`, disabled `NotesV2Profile.json`, one use `NotesPermissionProfile.json`, and exact `control.activation-candidate.json` in a private staging directory. The helper is signed with the existing ARL Local Code Signing 2026 identity. The permission profile expires in 120 seconds and binds the exact signed Control certificate and bundle ID, helper certificate and bundle ID, helper CDHash/executable/designated requirement, source closure, request UUID, epoch, capability, private journal inode, and one manual request. It only allows `notes.search.v1`, `notes.read.v1`, or `notes.create.v2` Automation permission setup. The installed Control already has the two step **请求权限… → 继续** entry; this source increment also adds **检查系统权限**, which uses only `permissions_snapshot` (`ask=false`) and never consumes the request UUID or calls `permissions_request`.

Installation would require a separately reviewed exact signed helper and placement of the exact candidate JSON at private `notes-v2/control.json`, then a Control restart and explicit user click. Observe the actual macOS Automation responsible app and halt if it differs. The user must be told the exact ARL/Notes helper scope before the click. The one use profile expires regardless of OS grant. Permission alone does not enable search, read, create, append, or Mio publication.

The current installed app still lacks `ARLNotesBridge.app` and `notes-v2/control.json`, so the user click entry remains hidden until the separate packaging/install review. A later data operation needs its own selected nonshared folder, fixed producer/FD handoff, budget, native review, and explicit authorization.
