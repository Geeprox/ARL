# One Mio capability entrypoint — bounded draft v1

2026-10-01. Preserve existing tunnel `<USER_TUNNEL_ID>` / plugin `<USER_PLUGIN_ID>`. Current public surface is the unchanged13 read tools. Weather is the independently tested14th candidate; not published. No second gateway service, tunnel/key, generic shell/container/file/URL/invoke tool or runtime-loading of caller code.

Small host-owned module table: approved module ID/version/owner and fixed adapter function; capability descriptor includes `action_id,version,input_schema,output_schema,schema_sha256,effect(read|write|send|actuate),permissions,confirmation,readiness,checked_at_ms`. Discovery returns only separately publication-approved descriptors (bounded100, paginated if larger), never granting access. A future `mio_capabilities_v1` read tool is a separate publication delta; it does not hold up weather14 and is not implemented/published now. Exact schemas reject unknown fields; breaking semantics get a new version and review. Existing13 names/arguments/results remain compatible.

Each action separately enforces verified local adapter identity, authenticated remote principal/policy, target/resource scope, call/byte/time budget and confirmation. Tunnel authentication proves a connection, not Apple/household write authority. Caller `owner/app/confirmed:true` cannot confer grants. Read permission never includes write/send/actuate; capability discovery and connected status never imply authorization. Apple Calendar/Reminders/Notes/iMessage are action-gated; ARL does not silently request TCC. HA endpoint/auth/device map/rules and NAS access stay in Friday/owning app. Mio→ARL→Friday calls only approved typed Friday capabilities, never HA directly.

Readiness states: `ready/starting/unavailable/disabled/needs_permission/needs_unlock/not_implemented/unknown`; authorization is independent `allowed/denied/not_checked`. `ready` requires current evidence for that particular action. Local tunnel health ready is transport evidence, not an end-to-end provider probe or ARL private grant. The new source-only `integrations/mio_status/status.py` measures owned fixed-loopback healthz/readyz with a hard2s subprocess deadline, reports only fixed states and reviewed-manifest hash/count; reports `external_roundtrip=not_checked`, `live_publication_verified=false`, `providers=not_probed`. It is not yet added to installed overview/schema2. Proposed UI handoff is a separate `settings.modules_snapshot` schema1 read-only method using this exact sanitized shape, **not registered until coordination/review**; no silently added v2 keys or client/UI edits.

Stable new-adapter errors: `invalid_arguments/unsupported_version/unknown_action/identity_unverified/permission_denied/needs_permission/needs_unlock/not_implemented/not_ready/transport_not_enabled/credential_unavailable/rate_limited/deadline_exceeded/provider_unavailable/invalid_provider_response/response_too_large/location_mismatch/no_data/idempotency_conflict/stale_target/confirmation_required/confirmation_expired/outcome_unknown`. Finite code + retryable flag + operation ID if one exists, no raw provider exception/URL/token/content. Per-adapter emitted subset is explicit; these draft errors do not claim an existing global service enum. Retry read failures only within policy/deadline; never automatically retry an uncertain write/send/device action. Current weather has no automatic retry.

Friday lights-off contract candidate: read/resolve opaque Friday target and fresh state; prepare `set_power(false)` for exactly enumerated targets, operation UUID, desired state, prior state/version, plan hash and expiry. No toggle/wildcard/free HA service payload. An ambiguity returns clarification_required, rather than selecting a room/device. Friday decides whether the user's explicit instruction is already authorized or a bound confirmation ticket is required; ticket must originate a trusted approval path, bound to principal/targets/plan/version/expiry and verified server-side—never an LLM's boolean. Execute exactly that plan once; replaying the same UUID queries the same operation. Changed plan/version is conflict/stale_target, not new execution.

Actuation result states: `prepared/confirmation_required/accepted/executing/confirmed/partial/failed/outcome_unknown`. Include operation/plan/target IDs, desired state, actual observed state, observation/source timestamp and nullable confidence. Only fresh Friday read-back with relevant device evidence yields confirmed; HTTP200/command accepted is not “light off”. Per-target partial results remain partial. Timeout/disconnect/cancel after dispatch is outcome_unknown and requires reconciliation; cancellation cannot promise undo. After restart no blind replay; read original operation/physical state. ARL preserves Friday's safety policy and does not invent success. This path is intended but not connected or published.

Concrete order: independent weather14 review/publication+one current/forecast real read; wire approved Mio local status reader with explicit metadata API/UI handoff; separately finish signed EventKit single-operation helper/approval; register Friday bounded state/operation adapter then mock+isolated native acceptance, and only approve actual device scope/publication afterwards. No generic framework is required for these fixed dispatch additions.

Future iMessage only: ordinary upstream imsg AppleScript send supports media/groups; attachments:true receive is metadata/path, not bytes, and missing:false is not proof of readable/downloaded content. A later adapter must check/retry file readiness separately from bounded vision/video routing. No account/message/TCC/deployment action is authorized here.
