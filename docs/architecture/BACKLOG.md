# 架构治理任务池

优先完成能在仓内验证的全量迁移。跨模块复审时核对对外错误码、并发/持久性、正式打包入口和历史调用方。

| 顺序 | 区域 | 已确认的偏离或待验证的重叠 | 可交付的边界 |
| --- | --- | --- | --- |
| 1 | 应用场景、模型套餐 | `AppConnections ↔ ApplicationPlatform` 耦合 SDK 校验与服务装配。场景、模型协商、配置分别列出相同档位 ID | 已完成 Python 迁移。五档顺序、默认值、旧显示名和接入行为由既有契约测试覆盖 |
| 2 | 宿主配置与身份、日志 | `host` 与 `compat_host` 重复定义账户目录、日志和 peer 组合。Research/Capture 层通过宿主回读装配原语 | 已完成。归并装配原语，三种设置策略保留原方法集，现有 Apple/NAS 的 Python 导入可继续使用 |
| 3 | Codex 请求构造 | `codex_server` 与两版研究模块互相引用线程控制。版本化受限字段和审查摘要是契约 | 已完成。由发送原生请求的 adapter 定义线程控制，研究证据引用同一值。v1/v2 控制摘要与 v2 公开合同摘要一致 |
| 4 | Friday 与优先级 | Friday 与优先级 host 装配形成双向依赖，审核和宿主分别硬编码同一模型 | 已完成。规划模块持有模型与准入类型，历史入口保留类型身份 |
| 5 | JSON 与错误边界 | `wire.strict_json`、部署规划、Capture 与 Friday 独立实现重复键及非 JSON 数值常量处理 | 已完成共同规则迁移。各入口持有原错误码、输入边界、深度和业务 schema。安装/同 UID 历史入口按现有输入规则读取 |
| 6 | Store / 调度与缓存 | App 场景层直接建表、查询和写入 SQLite，Native 日志同时维护版本化与 legacy 分页 | 场景任务和队列查询已迁移 Store。旧 v4 记录与回滚、配额、回放和本地监听均已验证 |
| 7 | 原生管理面与设计系统 | Swift 套餐身份、显示名和校验集合散落。日志 RPC 横跨视图和运行时状态 | 原生套餐定义已统一并增加跨语言测试。日志网络与解码归 `SettingsService`，缓存和分页保留经过回归的状态语义 |
| 8 | 环境变量与构建 | 构建工具重复推导缓存根与指纹。定向 native 检查也会生成无关旧夹具 | 工作树缓存根、源码指纹和夹具准备已归一。签名、封包及验证 profile 继续由对应配方和清单约束 |
| 9 | NAS 设置、读取、变更 | Core、Mio、Finder、NAS worker 与 UI 处理不同授权阶段 | 已合入 main 的统一选目录和范围护栏。跨进程状态归一需要在真实 NAS 上核对加密会话、目录范围和写后回执 |
| 10 | 目录与依赖方向 | 部分旧 Apple／外部路径仍被封包或 pin 引用 | Python 导入图已无循环。历史文件退役需核对现用版本和下游，目录拆分按要解决的职责与验证边界评审 |

## 查重后的兼容边界

| 重叠 | 当前保留条件 |
| --- | --- |
| `calendar_review.private_json` 与 `reminders_review.private_json` | 历史 Apple 包分别覆盖个别文件到冻结 Core。共享实现需要同时更新两份封包、批准清单和原生验收 |
| 正式 `arl/codex_packages.py` 与 NAS v2 的旧副本 | NAS stage 直接从固定路径覆盖冻结宿主，并有独立支持版本。需核对 NAS 运行时和下游回放，再决定升级或退役 |
| Tisra SDK hardening、Mio weather 与旧测试服务的重复函数 | 已冻结输入、历史评审证据或合成测试。处置依据是实际发布/pin 引用和保留周期 |
| `arl_nas_ui_composition`、正式 NAS Setup，及读／写路径约束 | `settings_channel.py` 仍调用 Python 设置接口，正式 NAS 包另由 `stage_nas_runtime.py` 选择输入。读范围、写入位置和上传计划的授权语义各自独立 |

## 要求产品或部署决策

| 事项 | 需要确认的契约 |
| --- | --- |
| 旧版 Apple、Mio、Tisra 和 Friday 入口退役 | 在用版本、历史回执读取及外部有效签名/pin。Friday 历史候选只收集顶层 Python 文件，若继续签发需同步评审封装清单和消费者校验 |
| 任务数据库、权限或兼容模式变更 | 已安装数据的跨版本恢复、备份/回滚、权限事实和批准范围 |
| 原生模块物理拆分 | SDK/Finder/Mio 的源码和签名配方、对外符号及正式包验收。优先延续当前编译组里的职责收敛 |
| 签名安装与真实业务 | 正式包、设备、账号、系统权限及文件写入验收范围。当前治理以可复现的源码、合成 transport 和独立验证为边界 |
