# 网易云投影错误上下文

这是长期保留的失败诊断，不是临时关键词开关。仅 `projectRead` 抛出错误后执行一次，随即重抛原错误；成功读取、请求参数、端点、权限、账号状态和写入流程保持原样。

已有签名 owner 只向 Mio 返回投影后 DTO；Node 用固定入口与 `--permission` 启动，没有 inspector 权限或外部 hook。故需一次显式签名资源修订，复用原生 executable，不需要新增 Swift、权限或框架。旧 one-read-observer 从未签装，不纳入此修订。

结构字段：`s` 阶段 1 search / 2 user_playlists / 3 playlist_detail / 4 tracks；`r` 原有有限错误编号；`t` data 类型；`q` 为直接候选键数量、其中数组数量、候选键位图。歌曲候选顺序为 songs/list，歌单为 playlists/playlist/records/list。因此 0 键与 2 键有独立事实。

`n` 是容器路径与键名:类型列表，`a` 是数组路径、长度、首元素类型及首元素字段类型。类型 X 未定义/其他、Z null、A 数组、O 对象、S 字符串、N 数值、B 布尔。从 `$` 广度优先检查至四层，最多12容器、8数组、每对象16键；覆盖 data.result.songs、data.data 等常见包装层级。数组元素内容不遍历，不记录标量值、曲目正文、账号、凭据或授权URL。仅允许32字符ASCII标识键名，敏感名称和命中当前秘密过滤器的键被排除；`h` 是排除数量。

`o` 的位1=键数限制，2=容器/数组数限制，4=深度限制，8=诊断预算精简。非零意味着上下文不完整，不能据缺失断言响应不存在某字段。预算不足优先去掉首元素字段和后部容器，保留候选数量和数组路径。诊断总帧最多128，预留8帧给结束阶段；诊断自身异常不会改变原错误。

既有原生协议只接受有限数值，不接收动态文本。结构JSON经过内置 zlib 压缩，按19位整数送入既有 sub_code；每个数仍在既有范围内。-97200 为版本/阶段/候选数量/类型/完整性摘要，-97201 为压缩字节数（0=预算不足），-97300 起为连续载荷块。它是受限字段名/类型传输，不能称为仅枚举诊断。使用 `script/decode_netease_projection_context.py` 解码已有的有限日志 readback；解码器检查完整块数、长度、解压上限、键/路径格式、隐私词过滤及摘要一致性。

必要验证只运行两条实际固定CLI合成调用：嵌套搜索返回保留原 -97030 并给出精确数组路径；正常搜索通过且没有错误上下文。另直接核对2候选键分支，确保不再混同0与2。真实网络与凭据均为0。这些验证不代表本机失败响应结构已经观察到；安装后的一次获准真实读取才提供该事实。
