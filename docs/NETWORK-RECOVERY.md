# 网络恢复与 ARL 的边界

节点故障恢复建议由独立的本地确定性守护脚本承担，使用 launchd 维护生命周期。脚本不依赖模型、云端 API 或 ARL 的任务执行队列；网络失效时仍能判断和切换。ARL 可以接收它通过通用注册协议报告的名称、图标与状态，但不参与每次切换决策。

先检查当前 Shadowrocket 配置是否已经提供适合的故障转移策略，避免两个恢复器互相切换。其开发者在 [App Store 产品页](https://apps.apple.com/us/app/shadowrocket/id932747118)说明了规则路由、连通性测试及策略组相关功能；这不证明某个具体版本存在可用的脚本切换接口。维护机只核对了已安装包的版本和 URL scheme 声明，没有读取节点凭据，也没有切换 VPN 或节点。具体切换命令、回读方式及无网操作仍需独立验证，不能把打开 URL 当作切换成功。

推荐实现流程：

1. 连续多次检查两个轻量目标，区分基础网络不可达、DNS 故障、代理不可达和单一目标故障；机器唤醒或网络切换后给出稳定等待期。
2. 仅在基础网络可达而代理失败时，按本地已配置候选逐一尝试。切换后重新检查实际出口及目标访问结果，不使用模型推测节点状态。
3. 单次恢复最多尝试三个候选，尝试间隔与失败冷却有上限；保持单实例，避免网络抖动时来回切换。尊重用户手动暂停或断开连接。
4. 不在故障时依赖更新订阅，也不写入或上传节点密码、订阅链接、代理 URL。记录有限状态码、计数和耗时即可。
5. 通过系统支持的本地接口执行并回读。接口不明确时先完成隔离验证，再开启自动切换。GUI 自动化只适合诊断或人工恢复。

本次交付只完成边界评估，未安装网络守护脚本、修改代理规则或改变节点。
