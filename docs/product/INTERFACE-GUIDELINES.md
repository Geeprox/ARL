# ARL 用户流程规范

新增功能与动作使用 2–4 个中文字符，说明每句不超过 20 字。动态名称、路径和用户正文保留完整；技术字段与限制放入“详情”，不得隐去授权、写入或未知结果的后果。

入口始终可见。进入页面只显示状态；业务检查、发现、授权和写入都由用户点击。已有授权直接进入下一步；拒绝后提供系统设置入口，不能循环申请。失败保留用户草稿并给出下一步。系统账号、应用登录、系统权限、业务连接和操作结果各自核验。

## Apple

信息：打开信息 → 在系统信息登录/设置地址 → 检查连接（无授权提示，只核权限和账户）→ 若待授权，点击连接授权 → 重查连接 → 选用账户 → 核对单个邮箱 → 核对全文 → 发送信息 → 系统接受或待核；送达仍到系统信息查看。ARL 不收 Apple 密码、不读通讯录，不以进程存活证明登录。手机号、历史、群聊、附件与 Mio 路由仍未接通，不能将单邮箱文字入口称为完整 iMessage。

备忘录：打开应用 → 检查权限 → 若待授权，点击连接授权 → 选择文件夹 → 查找标题/读取正文或确认新建。只操作选定范围。已有授权跳过申请；拒绝后到系统设置恢复。

提醒与日历：沿现有可见原生入口核权限、来源及所选范围；系统允许不等于业务验收。首次真实写入依现有确认流程，不因短文案简化而移除。

## 网络硬盘

查找设备或手填地址 → 共享与明确目录范围 → 保存范围 → 用户填登录 → 保存登录 → 手动连接 → 核验可浏览。固定只读；不提供不支持的读写和 SFTP。共享未知时可手填，不伪造枚举。高级事实、新文件测试和连接参数折叠；更换范围需重新填写登录的后果可见。

## 访达动作

随 ARL 提供原生扩展 → 用户在系统设置启用 → 在支持的注册目录内右键项目/空白处 → 访达动作 → 拷贝路径或终端打开。多选路径换行；终端仅单个目录，路径经文件 URL 传递，不拼命令。已挂载 NAS 仅用本机路径。FinderSync 不是通用全局界面 API，真实范围和启用状态必须验收；不注入、不模拟辅助功能、不新增守护服务。
