## 用户流程

1. 填写提醒内容，点击“确定内容”。只记录本条意图，不读取来源或保存。
2. 点击“选择范围”。在现有签名 helper 的原生窗口核对完整内容、来源和当前默认列表，再明确确认。本次只授权这条提醒，在五分钟内最多尝试保存一次。
3. 返回前台点击“确认创建”。写入持久尝试记录后，生产 v3 适配器仅向该列表创建一条提醒；不创建新列表、不修改已有内容。
4. 查看操作记录。本机保存和云端同步分别核验；回包未确认时先查同一记录，未知结果不重试。范围失效可重新确认，已尝试或取消的任务不能重新获得范围。

本包支持内容标题，不包含日期、告警、编辑、完成、删除或批量操作。新任务沿用现有双向认证 native socket、签名主体及 helper 生命周期，没有新辅助 App 或服务。系统提醒读写权限仍须用户单独申请；源码检查、元数据状态或历史复核都不能代替系统授权。

## 记录与授权边界

- 原验收 run、unknown 回执、原始证据、两次保存预算、请求目录及 operation journal 保持原样；原未知操作没有被换 run 重放。历史入口仍停止自己的测试保存。
- 新任务使用 `tasks-v1` 下独立的记录、请求目录和 operation journal；旧请求容量与未知结果不阻塞该目录中的合法新意图。
- 调用方只能提交内容与任务 ID。原生确认决定精确来源/默认列表，不能从请求 JSON 指定目标、预算或授权。提交前及实际保存前重新核对目标、当前代码身份、系统权限、期限和取消状态。
- 范围绑定当前 helper 会话与代码身份，使用单调时钟及墙钟期限。重启、代码升级、停用或到期后失效；记录仍可读取。
- 每条在任何可能保存之前持久标记为已尝试。提交后未知或中断只封住该条，另一条必须独立填写和确认；不清空、提升或自动重放未知结果。
- 新任务最多256条保留记录，请求目录有独立容量门禁，满后明确失败，不自动清除历史。列表每页最多5条，可恢复查看。后续正常归档属于独立产品工作。
