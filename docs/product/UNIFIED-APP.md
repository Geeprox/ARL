# 一个 ARL 应用

交付单位是正式 ARL.app。用户只安装、启动、升级和管理 ARL；构建依赖脚本不成为长期辅助产品。

## 组成

- 主程序：原生管理面、原生凭据与有界工具 owner。
- app 内后台入口：私有状态目录、核心队列、Codex 协议、应用会话、固定生命周期。
- app 内隔离进程：Mio 客户端/受控网关、必要 Apple helper。保持其稳定签名身份以保留 TCC，生命周期由 ARL 管理。
- app 内 Finder 扩展：系统要求的 FinderSync 组件，用户在系统设置启用。

隔离是处理取消、进程故障、工具超时和系统授权身份的边界；不等于要用户安装多个应用。现有音乐与授权不能为追求单进程而破坏。

## 已统一安装后的升级

旧版迁入统一 App 的正式切换已完成；后文 build58/59 等为迁移与故障恢复历史记录，不代表仍运行旧入口。 build73 已以 fresh transaction 完成后续正式升级，单 owner、实际子进程、读取 listener、源码与签名库存回读通过；原登录、profile/activation 和授权范围保留。

后续升级沿用包内管理事务。计划准备先核新旧签名、代码绑定、实际 owner/子进程、版本、资源与数据库 schema；仅更新 App 及既有代码消费者绑定。启动项内容、隧道 profile/activation、账号、授权与业务数据保留。未知原像或作用域漂移时明确停止。

停机区分旧独立 Mio 与统一 App 所有的 Mio：后者先请求已核 ARL 正常退出，排空业务、子进程并移除自有读取 socket，再卸载原 launchd job；不可用 SIGTERM 代替正常退出。等待同代进程与服务的明确结束，短暂身份查询失败仍为待确认，不能算完成。恢复后台 owner 不再重复 open 同一 App。事务保留原像；新包先在维护状态验证，再开放业务，失败按原流程恢复。实现与合成检查不等于真实升级完成；最终候选仍需独立审查、正式安装和运行回读。

## 已确认漂移（迁移前记录）

安装中的 research-product-optin 后台使用 app 外 run_host.py，入口固定历史 source commit/tree，当前源码和 UI 升级不会自动更新它。旧 metadata-only 管理器不能覆盖这一 profile。Mio 为独立已安装签名 bundle，需核归属与消费者后迁入 ARL 内；不能复制一个新隧道或让两套服务同时写。

## 迁移规则

1. 只读取安装、启动、版本、协议和授权元数据；不读取任务正文、联系人、私人笔记/信息、密钥。
2. 核对原 owner、consumer、状态目录与稳定身份。新包包含后端/原生 UI 的同一源版本和固定资源清单。
3. 新入口保留当前 opt-in profile、身份、scope、凭据与日志状态，不自动授权新应用/模型/工具。
4. 迁移前明确停止/接管的已核实例和 launchd label，按有限 deadline 排空；不按名字盲杀。
5. 同一事务切换后端/管理面，核验实际运行路径、版本、协议、会话和既有授权；失败恢复原入口/包，保留未知结果。
6. 旧持久入口的移除最后执行；未确认新实例与消费者正常时保留可恢复记录，不删除数据或重置 TCC。

## 发布边界

本机私有 compatibility code 与已批准配置不进入公开默认分发。公开核心无历史候选已有实际启动/零 grant 验收；完整原生发行仍需用户选择许可证/签名身份，并核清所有外部路径及资源。不能把核心候选称为完整 ARL 开源完成。

## 本轮实现与待切换

已实现：完整核心源码与固定入口进入 `Contents/Resources/CoreRuntime`；源码/资源清单绑定原生 Info.plist；同包 Python 使用 NAS 内置解释器。ARL 主进程持有核心和 Mio 子进程，退出先排空，不自动重放业务写入。父进程死亡时核心/Mio 停止自己的实例。异常在概览显示并提供恢复；恢复必须先证明旧实例已结束。

Mio 进入 `Contents/Library/LoginItems`，保留原证书、bundle ID、owner authority 与固定隧道客户端。仅迁移网关路径、相应 profile hash 与已封存策略 hash；不增加工具、账号、scope、权限或期限。隔离测试已验证核心实际 RPC/父进程退出，以及 Mio 既有连接、重复实例、重连、退出和有限日志。

生产切换尚未执行：需要定向审查、当前 owner 排空、同一事务切换 App/sidecar/启动项/策略绑定并准备回滚、实际路径与版本回读。当前包内入口依赖精确本地 `unified-runtime.json` 迁移标记；未迁移时不会抢占旧运行时。原有程序、状态和凭据继续保留。

生产迁移事务及 App 内管理入口已实现，并通过合成故障恢复验收；build58 的真实计划准备及状态读回已通过，待独立复审和旧窗口正常退出。不能把“同包构建”称为“统一安装已完成”，也不能先单独安装新管理面。
